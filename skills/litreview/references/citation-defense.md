# 引用防御六层

来自对 PaperQA2（Future-House，9010★）、AutoSurvey（NeurIPS 2024）、STORM（Stanford，30894★）、OpenScholar（AI2）的源码级调研，按性价比排序。

任何生成学术引用的环节都要过这六层。**只能做三件事时，选第 1、5、4 层** —— 前两者近乎零成本，第三者是学术级严谨度的分水岭。

---

## 第 1 层 · 不透明键 + 白名单（回报最高）

引用键**不要**用 `[Smith 2023]` 这种格式。改用检索时生成的不可猜测键：

```
pqac-a1b2c3d4
```

**为什么这是关键设计**：`[Smith 2023]` 模型凭预训练记忆就能顺手编出来 —— 它见过成千上万个这种格式，生成一个看起来合理的毫无难度。而哈希键是检索时才生成的，模型**猜不出来**，编造的键必然不在白名单里。

> 这一层把「语义幻觉检测」这个难题，降级成「集合成员判定」这个易题。

配套做法：
- 上下文末尾显式给出 `Valid Keys: pqac-a1b2c3d4, pqac-e5f6g7h8, ...`
- 用正反例明确禁止自由格式引用：

```
合法：[pqac-a1b2c3d4]
非法：[Smith et al. (2023)]、[1]、(Smith 2023)
```

PaperQA2 的实现（`src/paperqa/prompts.py`）：
```python
CONTEXT_OUTER_PROMPT = "{context_str}\n\nValid Keys: {valid_keys}"
```

## 第 2 层 · 标题当引用键（与第 1 层互补）

AutoSurvey 的路线：写作时用论文**完整标题**作为引用标记。

```
[Language models are few-shot learners; PaLM: Scaling language modeling with pathways]
```

**为什么有效**：数字编号是**语义空洞**的 —— 模型把 `[2]` 写成 `[3]` 时，两者都"看起来对"，无从察觉。而标题是**语义承载**的：
- 写作时模型必须想清楚自己在引谁
- 事后可以对数据库做标题查表，**查不到即为编造**

哈希键让"猜不出"，标题让"可核对"。两条路互补：内部用哈希，写作层用标题。

---

## 第 3 层 · 抽取与写作解耦（两段式）

不要让同一次调用既读原文又写结论。分两段：

**第一段 · 证据抽取**（用便宜模型，量大）

prompt 明令 **"不要直接回答问题"**，只做支撑性摘要 + 输出 0~10 相关度分。低分丢弃。

```
对以下文本片段做摘要，保留具体数字、效应量、带引号的原文表述。
不要回答用户的问题 —— 只提取可能支撑或反驳它的证据。
输出 JSON：{"summary": "...", "relevance_score": 0-10}
证据不相关时 summary 留空、score 填 0。
```

**为什么"不许回答"很关键**：一旦允许模型在抽取阶段就下结论，它会开始用先验知识补全，抽取就被污染了。把抽取和推理解耦，是抑制早期臆断最有效的一招。

**第二段 · 基于已核验摘要写作**（用强模型）

一个容易漏的细节：**剥离证据块中原文自带的引文标记**。

论文原文里常有「先前研究表明 X[12]」这样的句子。如果不剥掉那个 `[12]`，模型会照抄它，结果变成"引用了一个自己没读过的二手来源"。PaperQA2 有 `skip_evidence_citation_strip` 开关，默认剥离。

---

## 第 4 层 · 语义级校验轮（学术级的分水岭）

生成后**单独跑一轮**，只做一件事：判断每条引用是否真能支撑对应的句子。

AutoSurvey 的 `CHECK_CITATION_PROMPT` 判据写得极明确：

> 正确的引用意味着该论文的内容**能够支撑**你写的句子。一旦引用无法支撑该句，**修正 `[]` 里的标题或直接删除它**。……**除引用之外不得改动任何其他内容。**

最后一句是关键约束 —— 否则校验轮会顺手改正文，引入新的未核验内容。

**这一层专抓「A、B 都真实存在但张冠李戴」** —— 白名单（第 1 层）和编号越界检查（第 5 层）都抓不到这类错误，因为两个引用键都是合法的，只是配错了句子。

STORM 缺的正是这一层：它只校验编号合法性，模型把 `[2]` 错标成 `[3]`（两者都存在）时发现不了。

OpenScholar 的 `posthoc_at`（事后引用归因）是本层的变体：先自由生成，再为每个句子反向匹配支撑文献。

---

## 第 5 层 · 确定性后处理（不花 token，必做）

纯代码能做的事，不要交给模型。

**越界编号强制抹除**（STORM 的做法）：

```python
# 本节只有 5 条来源，模型写了 [7] —— 直接删掉
if max_ref_num > len(current_section_info_list):
    for i in range(len(current_section_info_list), max_ref_num + 1):
        content = content.replace(f"[{i}]", "")
```

**参考文献表从正文反推**（PaperQA2 的 `used_contexts`）：

```python
def used_contexts(self) -> set[str]:
    # 只保留真正出现在正文里的
    return {c.id for c in self.contexts if c.id in self.raw_answer}
```

这条杜绝两类错误：列了但没引（虚假充实）、引了但列表里没有（悬空引用）。**绝不预先假定参考文献表** —— 必须从正文反推。

**按正文出现顺序全局重编号**，并删掉未被引用的来源。

---

## 第 6 层 · 允许拒答 + 温度归零 + 撤稿检查

**允许拒答。** 必须给模型一条合法退路：

```
CANNOT_ANSWER_PHRASE = "根据现有证据无法回答"
```

并让上层识别为失败（而非当成有效答案）。理由很直接：**"必须给出答案"的压力，必然被幻觉填满。** 不给退路等于要求模型编造。

**温度归零。** 生成引用相关内容时 `temperature=0`。检索式生成、引用校验这类任务需要可复现 —— 同样输入应得同样输出。

**撤稿检查。** 这一条最容易漏，危害却最大：

> 引用一篇**已撤稿**论文，比引用一篇**不存在**的论文危害更大 —— 后者审稿人一眼看出，前者会跟着你进正式发表。

各源的撤稿标记位置：
- PubMed：`PublicationType` 含 `Retracted Publication`，或 `CommentsCorrections` 的 `RefType="RetractionIn"`
- OpenAlex：`is_retracted` 字段
- Crossref：`update-to` 里 `type=retraction`
- Europe PMC：`commentCorrectionList` 里 type 以 retraction 开头

另有 DOI 层面的防伪：`"不要编造形如 10.xxxx 的 DOI"`，查不到就不写。

## 长文分节生成的顺序铁律

引用防御和写作流程耦合，顺序错了防御会失效：

```
先检索 → 再定大纲 → 后写作          （大纲必须从已检索到的材料长出来）
每节独立检索、独立上下文、局部编号、并行生成
→ 引用校验轮（第 4 层）
→ 跨节连贯性润色                    （此轮禁止改动引用）
```

**为什么润色必须在校验之后且不能碰引用**：AutoSurvey 的 LCE（Local Coherence Enhancement）把「前一节 + 本节 + 后一节」一起给模型润色本节，并硬性规定 *"Do not modify any citations in [] following the sentences."* 如果润色能改引用，前面辛苦校验的结果会被污染。

**为什么每节独立上下文**：一节只给它自己的 top-k 来源（STORM 用 `retrieve_top_k=5`，info 限 1500 词）。小编号空间 + 小上下文 = 错引概率显著下降。而且能并行提速。

## 一条反直觉的经验

OpenScholar 证明：**钱花在 retriever 和 reranker 上，8B 小模型就够**。

检索质量对最终引用准确性的边际收益，通常高于换更大的生成模型。如果引用老是不准，先检查检索到的证据对不对，而不是急着换模型。
