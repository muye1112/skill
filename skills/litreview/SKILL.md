# 文献综述全流程

这个技能覆盖从一句研究问题到一份带可核查引用的综述草稿的完整路径。它把七个阶段串成一条流水线，每个阶段都可以单独执行、单独重跑。

## 为什么需要这个技能

三个反复出现的失败，任何一个都会让综述作废：

**中文检索不到文献。** PubMed、OpenAlex、Crossref 都不索引中文。实测「肠道菌群 AND 抑郁症」返回 0 篇，而 `gut microbiota AND depression` 返回 3877 篇。用户往往以为是工具坏了，其实是语言问题。所以第一阶段必须做概念到英文主题词的转换，而不是字面翻译。

**AI 编造或错配引用。** 这是投稿综述唯一致命的失效模式 —— 审稿人一旦发现，全文失去信任。引用已撤稿论文更糟，因为它会跟着进正式发表。所以引用防御要分六层，写在 `references/citation-defense.md`。

**罗列文献而非综合文献。** 「张三等研究了……李四等研究了……」这种写法是研究生最常被退稿的问题。Results 必须按**主题**组织，在主题内跨研究比较一致与矛盾。

## 七个阶段

完整方法学依据 PRISMA 2020，详见 `references/prisma-workflow.md`。

### 阶段一 · 立题

先把研究问题结构化，否则后面的检索式无从生成。

用 PICO 框架（临床/干预类研究）：
- **P** Population 研究对象
- **I** Intervention 干预措施
- **C** Comparison 对照
- **O** Outcome 结局指标

观察性研究用 PEO，质性研究用 SPIDER。

同时确定综述类型 —— 它决定后续严格程度：

| 类型 | 需要 PRISMA | 需要质量评估 | 说明 |
|---|---|---|---|
| 叙述性综述 Narrative | 否 | 否 | 研究生最常写的 |
| 系统综述 Systematic | 是 | 是 | 需预注册（PROSPERO） |
| 范围综述 Scoping | PRISMA-ScR | 可省 | 探索领域边界 |
| Meta 分析 | 是 | 是 + 发表偏倚 | 需统计合并 |

选了叙述性综述就不要逼用户做 RoB 偏倚评估 —— 那是系统综述的要求，用错了是负担而非严谨。

同时定下纳入/排除标准：时间范围、语言、出版类型、研究设计、样本量下限。这些会自动进入综述的方法学章节，用户不用手写。

### 阶段二 · 检索

**核心动作：中文问题 → 英文检索式。**

不是逐词翻译，而是概念映射 + 同义词扩展 + MeSH 主题词。做法见 `references/search-strategy.md`。

生成后必须把检索式**显示给用户并允许修改**。不要做黑盒 —— AI 偶尔会漏关键概念，用户一眼能看出来。这一步省不掉。

各数据库语法不同，直接把 PubMed 检索式发给别的库会得到 0 结果或垃圾结果：

| 数据库 | 语法特点 | 速度 |
|---|---|---|
| PubMed | 支持 `[tiab]` `[MeSH Terms]` `[pt]` `[dp]` | 快，有 MeSH |
| Europe PMC | 支持布尔，字段名不同 | 最快，字段最全，OA 全文 |
| Semantic Scholar | 只认自由词，布尔会被当普通词 | 快，带 TLDR，无 key 时限流严 |
| Crossref | 只有 `query.bibliographic`，不认布尔 | 中，DOI 权威 |
| OpenAlex | 支持布尔，不认字段限定 | 从国内访问极慢，标为慢源 |

转换脚本：`scripts/translate_query.py`

**检索式必须完整记录**（PRISMA-S 要求）：数据库名、检索日期、时间范围、完整检索式、命中数。这段原样进入综述附录 A。很多研究生被审稿人挑的正是这一点。

**零结果时给诊断**，不要静默失败。常见原因：含中文、AND 过多导致过窄、MeSH 词拼写不标准、年份限制过紧。

### 阶段三 · 去重

三级去重，顺序不能颠倒：

1. **DOI** 精确匹配（归一化后，最可靠）
2. **PMID / PMCID / arXiv ID** 匹配
3. **标题模糊匹配**（归一化后编辑距离 ≥ 0.95）

相似度在 0.85~0.95 之间的进**人工复核队列**，不自动删。静默删除会丢数据，而 PRISMA 要求可追溯。

一个必须处理的边界：标题几乎相同但年份差 2 年以上的，**不要自动合并** —— 可能是勘误、再版或不同研究。

去重不只是删除，还要**信息互补**：同一篇文献在不同源的字段互相补全（OpenAlex 有被引数、Europe PMC 有全文链接、PubMed 有 MeSH 主题词）。

脚本：`scripts/dedup.py`

### 阶段四 · 筛选

PRISMA 规定的两阶段：

**4a 标题摘要筛选** —— 只读标题和摘要，快速排除明显不符的。可以用便宜模型批量打 0~10 相关度分辅助排序，但**判定权在用户**。

**4b 全文筛选** —— 对通过 4a 的获取全文，按完整标准复核。

**每次排除必须记录原因**，进综述附录 C。预设原因：研究对象不符、干预措施不符、对照不符、结局指标不符、研究设计不符、非目标语言、会议摘要无全文、已撤稿、重复发表、其他。

全文获取四层兜底：
1. Europe PMC / PMC 开放获取（自动）
2. Unpaywall 找合法免费版本（自动，命中约 40~50%）
3. 用户手动放入 PDF（拖入即解析）
4. Zotero 浏览器插件保存（用用户自己的登录身份，处理付费墙）

### 阶段五 · 抽取

对纳入的文献做结构化抽取，字段固定（依据 Cochrane 数据抽取表）：

```
研究 ID：作者 / 年份 / DOI
研究设计：RCT / 队列 / 病例对照 / 横断面 / 其他
研究对象：n= 、年龄、场所
干预或暴露：
结局指标：主要 / 次要
结果：效应量、95%CI、p 值
质量评级：低 / 中 / 高 偏倚风险
资金来源与利益冲突：
```

质量评估工具按研究类型选：RCT 用 Cochrane RoB 2，观察性研究用 Newcastle-Ottawa 或 ROBINS-I，诊断准确性用 QUADAS-2，系统综述用 AMSTAR 2。

抽取时**每个数值都要能指回原文位置**。这是后面引用校验的基础，也是"证据优先"的含义。

### 阶段六 · 综合

**这一阶段决定综述质量，也最容易做错。**

不要逐篇摘要。要按主题组织，在主题内跨研究比较。

正例：
> 多种递送方式被研究。病毒载体（AAV）用于 15 项研究[1-15]，转染效率高（65~85%）但存在免疫原性顾虑[3,7,12]。相比之下，脂质纳米颗粒效率较低（40~60%）但安全性更好[16-23]。

反例：
> 张三等（2023）研究了 AAV 递送……李四等（2024）研究了脂质纳米颗粒……

做法：
1. 从纳入文献中识别 3~5 个主题
2. 与用户确认主题划分（一篇文献可属多个主题）
3. 每个主题下写：一致的结论 / 矛盾的证据 / 证据强度

详见 `references/synthesis.md`。

### 阶段七 · 撰写

标准章节结构见 `assets/review-template.md`。

**自动填充的部分**（用户不用写）：方法学的检索策略（来自阶段二记录）、纳入排除标准（阶段一）、结果的文献选择数字（PRISMA 计数）、附录 A/B/C/D/E。

**AI 起草、用户核对的部分**：主题综合、讨论、结论。

生成顺序有硬性要求：

```
先检索 → 再定大纲 → 后写作     顺序不可颠倒
每节独立上下文 + 局部引用编号 + 并行生成
→ 引用校验轮（语义级）
→ 跨节连贯性润色（此轮禁止改动引用）
```

顺序反了会污染已核验的引用 —— 润色轮如果能改引用，前面的校验就白做了。

## 引用防御（六层，必读）

任何生成引用的环节都要过这六层。完整说明见 `references/citation-defense.md`，这里只列要点：

1. **不透明键 + 白名单** —— 引用键用检索时生成的哈希（如 `pqac-a1b2c3d4`），不用 `[Smith 2023]`。模型猜不出哈希，编造的键必然不在白名单里。这把"语义幻觉检测"降级成"集合成员判定"。
2. **标题当引用键**（与 1 互补）—— 写作时用论文完整标题。数字编号语义空洞、写错无从察觉；标题可对库查表，查不到即为编造。
3. **抽取与写作解耦** —— 便宜模型只做"摘录 + 相关度打分"，明令"不要直接回答问题"；剥离证据块中原文自带的引文标记，防止照抄二手引用冒充一手来源。
4. **语义级校验轮** —— 独立一轮判断"该论文内容是否真能支撑该句"，动作是修正或删除，且严格限定"除引用外不得改动任何内容"。这一层专抓「两篇都真实存在但张冠李戴」，是学术级严谨度的分水岭。
5. **确定性后处理** —— 越界编号强制抹除；**参考文献表从正文反推**（只保留真正出现在正文里的）；按正文顺序全局重编号。不花 token，必做。
6. **允许拒答 + 温度归零 + 撤稿检查** —— 给模型「我无法回答」的合法退路，否则"必须给答案"的压力必然被幻觉填满。生成引用时 temperature=0。撤稿检查不可省。

校验脚本：`scripts/verify_citations.py`（查 Crossref 确认 DOI 真实存在并比对标题）

## 关于图片和图表

如果当前环境能读图（Codex 可以），精读阶段务必看图 —— 论文的核心结果常在图里，只读文字会漏。

如果环境读不了图，要**明确告知用户**这一限制，不要假装看过。可以让用户描述图的内容，或改用能读图的环境。这一点不能含糊：声称看过一张没看的图，等于编造证据。

## 一句必须说给用户的话

AI 产出的是**草稿**，不是能直接投稿的成品。

调研过的开源项目里，STORM（斯坦福，30894★）官方明确声明产物达不到可发表水准、需大量人工编辑。目前没有任何工具能端到端产出可投稿的综述。

所以定位是：**引用可溯源的高质量初稿 + 人工精修**。界面上让每句话都能点回原文出处，方便核查 —— 但核查这一步无法省略。把这句话说清楚，比多写一千字草稿更有价值。
